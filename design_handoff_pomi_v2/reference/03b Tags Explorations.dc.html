Pomi · tags
Where do tags live while you're working?
Four answers to the same question, cheapest chrome first. Constraints I'm designing to: tags are text with an optional colour, several can be on at once, none is a valid state, and turning one on or off cuts the timeline at that instant — so the UI has to read as "what's true right now", not "what this session is about". Every direction reuses the Amber Instrument tokens: Space Grotesk, paper #F3F0EA, ink #1A1916, ochre reserved for "get moving again" and for progress.
6
Past three, the handle has to change its mind
Agreed on both counts: five dots and nine dots were the same picture, and both +N and Add tag simply open the 2b sheet — one destination, no third screen. So the rule is now: one, two, three tags render literally as dots. Four or more switches to a different mark entirely — not a denser cluster. Four candidates for that mark, each shown at 9 on the phone and at 3, 4, 6, 9 and 20 in the strip beside it. The 3 → 4 jump is the thing to judge.

5
4b taken to its edges — and 2b left alone
The flow is settled: handle → tray → sheet. The handle and tray only ever show what is on right now; the moment you need the actual library you are in the 2b sheet — on-now, often-used, A–Z, search-and-create at the thumb — completely unchanged. So everything below is about the two new pieces holding their shape at counts they were not drawn for, and about the screens other than a running Pomodoro.
5a
The handle at every count
The handle is the one thing always on screen, so it has to survive every count without changing size. It does not: the cluster caps at four coloured dots and adds a single stone dot for “and more”, so the pill sits between 60 and 80 px wide from one tag to nine. The empty state is the important one — with nothing tagged there are no colours to show, so it spells out TAGS next to a dashed dot. That one is wider — 107 px — because it is carrying a word, and it is the state a new user meets first, so it can afford to be.

4
Outside the dial again — but able to get out of the way
You are right about the dots: a mark inside the dial reads as decoration to anyone who has not been told. So these all put readable, named tags back outside the ring, and each one solves “not always visible” a different way — dim it, hide it behind a handle, fold it away once the timer runs, or move it off the composition entirely. All four open the same 2b sheet, and every one has a state where the word TAGS is on screen, so a first-time screenshot explains itself.
4a
Labelled row that quiets down
Same row as 1a, but it earns its keep twice: for the first ten seconds after any change it carries a small TAGS label so a screenshot is self-explanatory, then the label drops and the whole row settles to about a third opacity. Nothing moves — the layout is identical in both states, so the dial never jumps — it just stops asking for attention. Touch anywhere on it and it comes back to full strength.

3
The mark under “Deep work” — five ways to show how many tags are on
No names, no counts, no chips — just a small mark inside the dial, directly under the phase label, sitting in a 44 px tap target. Tap it and you get the 2b sheet, unchanged, every time. Each mark carries the tag colours, has a defined empty state (a dashed hollow form = nothing tagged, tap me), and stops adding detail at a hard ceiling rather than degrading. The strip under each phone is the same mark at 0, 1, 2, 3, 5 and 8 tags on, so you can see where each one gives up.
3a
Dot row that packs
The plainest fun thing: one dot per tag in its own colour, spaced out while there is room. At five they slide into an overlapping stack — the same gesture a photo pile makes — and a stone dot closes the stack when there are more than five. You read “a few” or “a lot” without counting, and a single hollow dashed dot is the untagged invitation.

2
1a at scale — many tags on, and a big library
Two separate problems, so two separate answers. On the timer the row only ever shows what is on right now — that number is bounded by your own intent, not by library size, so it needs a hard cap and a collapse rule, never a wrap to three lines. In the sheet the number is unbounded, so it needs search plus a frequency shortcut — and the search field has to be reachable with a thumb, which means it sits at the bottom of the sheet, right above the keyboard, not at the top.
2a
The row: one line, always
The row is 34 px tall and stays 34 px tall forever — it never wraps, so the dial never moves. Up to three chips fit and scroll sideways under a paper fade; at four or more it folds into a summary chip carrying a dot cluster and a count. Either way the plus stays pinned outside the scroll so “add” is always in the same pixel.
